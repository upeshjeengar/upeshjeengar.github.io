The core idea

Feature engineering is where domain knowledge enters the model.

In deep learning, we often do not have to handcraft every feature because many features can be learned automatically by algorithms. Still, feature engineering remains important, especially when the model needs domain-specific processing such as text cleaning, text encoding, categorical handling, scaling, or leakage prevention.

Learned features reduce manual work, but they do not remove the need to understand the data, the task, and the production environment.

Missing values

Missingness has meaning, and the reason matters.

Before handling missing values, first understand why the value is missing. Different missingness patterns lead to different risks.

Type Meaning Example
MNAR Missing not at random. The value is missing for reasons related to the value itself. An unemployed person's income is not written.
MAR Missing at random. The value is missing because of another observed variable. People from a certain group may not like disclosing their age.
MCAR Missing completely at random. There is no pattern in when the value is missing. A field is randomly skipped because of a collection issue.

Deletion

  • Use row deletion when not many values are missing or when missingness is MCAR.
  • Use column deletion when more than 50% of values are missing.
  • The drawback is that you may remove important information and reduce model accuracy.
  • Removing rows can also create bias, especially when values are MAR.

Imputation

  • The hard part is deciding which values to use for imputation.
  • You can fill a missing job field with an empty string.
  • You can use mean, mode, or median based on domain knowledge.
  • With imputation, you risk adding noise or causing data leakage.
!
There is no perfect way to handle missing values.

With deletion, you risk losing important information or increasing bias. With imputation, you risk adding noise to the data, or worse, creating data leakage.

Common operations

Feature engineering often starts with scale, buckets, and categories.

Scaling

We should keep the scale of columns similar for some ML models, such as linear models. Otherwise, the model may give more importance to a column with larger magnitude values, such as income, even if age is more important for the use case.

Discretization

Discretization turns a continuous feature into a discrete feature. It is also known as quantization. For example, decimal-level income differences may not matter, so income can be grouped into lower, middle, and upper income buckets.

Choosing boundaries

To choose category boundaries, we can use quantile plots, histograms, and domain knowledge.

Categorical features

Categories are not always static.

We might assume categories do not change over time. That can be true in many cases, but in recommendation systems, new product brands can appear and the model may not recommend them. The same goes for new product types, website domains, restaurants, companies, IP addresses, and many other categories.

The hashing trick

The hashing trick generates a hash index for each category, so new categories can still be assigned into the prediction space.

The main problem is hash collision. Fortunately, the impact of colliding hashed features is often not too bad. In research by Booking.com, even with 50% colliding features, the performance loss was less than half a percent.

Feature crossing

Feature crossing combines two or more features to generate new features. It helps model nonlinear relationships between variables and is especially useful for models that cannot learn nonlinear relationships well, such as linear regression, logistic regression, and some tree-based models.

Embeddings

Position matters in language and vision.

First introduced in Attention Is All You Need in 2017, positional embeddings have become a standard data engineering technique for many applications in computer vision and natural language processing.

We need positional embeddings because position changes meaning. "A dog bites a child" is very different from "A child bites a dog." The embedding size for positions is usually the same as the embedding size for words so that they can be summed.

embedding("dog" at position 1)
  = word_embedding("dog") + position_embedding(1)

Learned positional embeddings

The model learns the best vector for each position during training. These positional embeddings usually start as random vectors.

Fixed positional embeddings

The original Transformer used sine for even dimensions and cosine for odd dimensions.

PE(pos, 2i)   = sin(pos / 10000^(2i / d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i / d_model))

position_embedding(pos) = [
  sin(...),
  cos(...),
  sin(...),
  cos(...),
  ...
]

position 1: [sin(1), cos(1), sin(1/100), cos(1/100)]
position 2: [sin(2), cos(2), sin(2/100), cos(2/100)]

These positional vectors are added to the corresponding word embeddings and then passed to the model.

Data leakage

Leakage makes validation look good and production fail.

Data leakage happens when test data, or information that should not be available during inference, enters the training process unintentionally. Technically, data leakage refers to the phenomenon where a form of the label leaks into the set of features used for prediction, and that same information is not available during inference.

Common causes of data leakage

Time-correlated data

Splitting time-correlated data randomly instead of by time can leak future information into training. If time affects the label, split by time.

Preprocessing before splitting

Scaling before splitting, or filling missing values with global statistics, lets information from validation or test data influence training.

Duplicates and correlated samples

The same example, related patient scans, or collection-process artifacts can appear across train and test splits and accidentally reveal label information.

Detecting data leakage

Measure the correlation of each feature, and combinations of features, with the target variable. Investigate unusually high correlations to ensure they are valid and not caused by leakage. Some features may appear harmless individually but reveal target information when combined. For example, when predicting how long an employee will stay at a company, start date and end date together determine tenure.

Do ablation studies. If removing a feature significantly hurts performance, domain knowledge is needed to decide whether that feature is truly important. If a feature should not be important but removing it still causes performance to drop, it can be a sign of data leakage.

i
Feature jumps need investigation.

If adding a new feature significantly improves model performance, either that feature is genuinely good, or it contains leaked information about the labels.

Engineering good features

More features are not always better.

Generally, adding more features can improve model performance. However, having too many features can be bad during both training and serving.

1

Leakage risk

The chance of data leakage increases as the number of features grows.

2

Overfitting

Too many features can make the model memorize patterns that do not generalize.

3

Serving cost

More features can increase memory requirements, latency, and cost.

4

Maintainability

Large feature sets are harder to debug, update, and monitor.

Feature importance

Feature importance helps explain what the model is using.

You can find feature importance statistically using bivariate analysis. More advanced methods include SHAP and InterpretML, an open-source package for interpretable models.

Feature generalization

Features should work on unseen data.

Since the goal of an ML model is to make correct predictions on unseen data, the features used by the model should generalize to unseen data. Not all features generalize equally.

For example, for the task of predicting whether a comment is spam, the identifier of each comment is not generalizable and should not be used as a feature. However, the identifier of the user who posted the comment, such as a username, might still be useful for prediction.
