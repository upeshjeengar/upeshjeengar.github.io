System walkthrough

How a ticket moves through INAIA

Route the ticket to the right support tier

  1. Read

    A backend triage agent reads ticket details from Jira Service Management.

  2. Classify

    It categorizes the issue as L1, L2, L3, or L4.

  3. Assign

    It weighs region and current ticket load to find an eligible engineer with the lightest queue.

Resolve first-line issues inside Jira

  1. Attempt resolution

    The L1 backend handles eligible requests directly, without an engineer in the routine path.

  2. Ask in context

    When details are missing, INAIA posts a clarification on the Jira ticket through the support integration.

  3. Resume

    Jira automation sends the customer's reply back to INAIA so it can continue the same case.

Give engineers a controlled path from ticket to fix

  1. Start from the ticket

    Engineers sign in with Atlassian to access their recent tickets. INAIA uses the relevant repository in an isolated Docker workspace for root-cause analysis with the Claude Agent SDK.

  2. Verify database issues

    For L2 cases, INAIA suggests diagnostic SQL. Engineers run it on production Oracle and share the results. INAIA uses sample data and has no production database access.

  3. Propose code changes

    For L4 bugs and change requests, the workflow can prepare a patch and open a Bitbucket pull request under the engineer's identity for review.
